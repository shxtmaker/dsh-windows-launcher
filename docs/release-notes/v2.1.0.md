# DSH Windows Launcher 2.1.0

发布日期：2026-09-15。候选：分支 `main`（合并自 `feat/remote-file-paste-attachments`），
`releaseStatus=candidate`，不签名自有产物（`distribution.signing.policy=none`）。

## 1. 本版新增：远程文件粘贴附件

在保留既有配对、`/remote` 代理、文本与原生图片能力的前提下，新增**本机文件/截图粘贴为远端会话附件**的完整通路：

```text
Windows 用户粘贴动作
  → 受控文件快照（只接受原生手势捕获的普通文件）
  → 带序号/ACK/限额/背压的分块 WebMessage
  → 页面构造真实 File
  → 附件插件草稿适配器
  → Harness 原有草稿与上传流程
  → 全家桶 /remote 认证代理
  → 原会话的待发送附件
```

- **原生手势与剪贴板**：只有真实原生粘贴手势才铸造短期一次性授权（绑定 target/epoch/焦点），
  不注册全局键盘钩子；STA 只做有界探测，读取与编码在线程池；文件列表恒优先于位图；
  同一动作只有一个消费者；DIB 走确定性 PNG 且护栏先于分配（40 MP / 20 MiB）。
- **文件快照与暂存**：真实 Win32（`CreateFileW` 独占、无跟随重解析点、限额先于分配、边拷边算
  SHA-256、来源变化检测、清理只动自有根）；拒绝 UNC/目录/重解析点/云占位/离线/远程卷。
- **分块线协议 v1（冻结）**：11 类消息、`operationId==batchId`、`seq` 每文件从 0、最多 2 块在途、
  256 KiB 块、36 个协议拒绝码与 19 个结果码分工不混用、重放缓存有界且活动操作钉住。
- **页面会话隔离**：每目标独立 WebView2 与独立用户数据目录；导航开始即撤销旧能力并推进代际；
  来源判定只做规范化后逐字相等（含 userinfo / IPv6 后缀伪装的负例）。
- **附件附加插件** `@shxtmaker/dsh-remote-attachments@0.1.0`：host/client 双半区；握手（版本/限额钳制/
  origin/会话身份）；三态可分离（transport / draft / upload=harness-owned）；逐文件部分失败账本；
  未知 hook ⇒ 能力冲突且不覆盖不贴牌；远端降级 ⇒ 能力不可用且**配对不受影响**、
  **不静默回退裸 `/api`**；停用与 `ReloadRequired` 双向可判定。

## 4. 附件插件安装

```bash
# 在目标 Harness profile 中安装本版附件插件（固定版本，不用浮动 latest）
pnpm --dir <profile-dir> add file:<path>/shxtmaker-dsh-remote-attachments-0.1.0.tgz
```

- 插件安装包：`shxtmaker-dsh-remote-attachments-0.1.0.tgz`
  （`sha256=64a359de44fd12185297ba8939268208246e61981bf149a1efd0591dfc3b996b`，59 文件）。
- 停用/回退：单独停用该插件只关闭附件能力，**保留**全家桶配对、心跳与设备库；
  页面能力恢复不等于 runtime 恢复，必要时明确提示并真实重载（`ReloadRequired`）。
- 若本版没有 Launcher 安装包：现有 2.0.9 安装的 EXE 不受影响，附件能力由插件与远端页面提供；
  正式 Launcher 安装包待 Windows 轨道产出。

## 5. 已知问题

1. **⚠️ `DshLauncher.Platform.Windows.Tests` 数据集转义隐患**：4 条含反斜杠参数的理论用例在真实
   Windows XML 门禁下会因 MTP 双重转义报 `missing/unexpected`（基线来自枚举 JSON 归一值）。
   Windows 轨道 W00 必须先按真实 XML 重新推导或统一转义归一；在此之前不得声称该程序集基线可用。
2. **口径**：`Session.promptError` 公开路径存在（插件 `ctx.sessions.scope(id)` → `sessionOf(scope)` →
   `getSnapshot().promptError`）；当前黑盒测试没有插件上下文句柄，不得表述为"没有公开接口"。
3. **撤销语义**：只表述为"请求到达 Host 前被门控拒绝"（403 + `unpaired`），不得扩展为
   "已通过鉴权的上传流被主动终止"。
4. 未验的受限场景：真实 npm 源更新流、市场更新、未安装的上游组合（见 `windows-task-list.md` §4.2）。
