# D25 · 冻结开发交付并移交 Windows 实机验证

轨道：DEV。状态以 `../execution/state.json` 为唯一真值；本任务卡不预置通过结果。

依赖：D24。默认下一建议：Windows 独立验收（需用户明确启动）（仅建议，不在同轮自动执行）。

## 单一目标

交付完整代码和同候选证据，将Windows实机作为单独任务轨道。

## 允许改动范围

- `docs/remote-file-paste/ 当前方案与执行记录`
- `候选与测试包manifest`
- `Windows待验清单`

## 执行步骤

1. 绑定commit或工作树内容摘要、lock、tarball和Linux证据；无自动正式版本升级。
2. 更新Windows输入材料、工具依赖、源码待编译项、原生用例、安装与回退方案。
3. 核对全部DEV任务和证据有效后记DevelopmentReady，Windows保持pending，结束开发调度。

## 必须交付

- 开发交接报告、tarball与manifest、Windows运行手册和任务列表。

## 本任务验收

- 不存在未完成业务代码或被误记通过的Windows项。
- 不自动启动Windows任务、正式打包/安装、推送、Release或npm发布。

## 失败与停止条件

证据因候选变化失效须回到受影响任务验证，不用旧版本报告充数。

本轮只完成本任务及其直接验证/局部修复。达到验收、出现具体阻断，或到达需要拆分的范围边界时，写入轮次记录与检查点并结束；不得转入下一任务。缺少 Windows 实机仅影响独立系统验收，不是跳过开发实现的理由。

## 轮末证据与恢复点

记录变更文件、实际命令/退出码/用例数、证据路径与被测候选摘要；列出未验项及所属轨道。状态为 partial/blocked 时写明已保留成果、剩余一步和解除条件；下一轮先核对工作树及进程再恢复。
