# D13 · 组合附加插件桥与能力状态

轨道：DEV。状态以 `../execution/state.json` 为唯一真值；本任务卡不预置通过结果。

依赖：D07、D08、D11、D12。默认下一建议：D14（仅建议，不在同轮自动执行）。

## 单一目标

把接收器接入原生草稿adapter，明确能力冲突和生命周期。

## 允许改动范围

- `插件caps/context/bridge组合`
- `设置与错误状态`
- `插件集成测试`

## 执行步骤

1. 实现hello/capabilities/context，版本、限额、origin和会话状态检查。
2. end成功后经adapter导入，staged与上传ready分开显示；部分失败可辨识。
3. 禁用/重启/页面重载时撤销自己拥有的hook与回调，原runtime捕获闭包的情况明确ReloadRequired。

## 必须交付

- 完整addon浏览器功能及能力检查测试。

## 本任务验收

- 全家桶remote降级或禁用时附件能力明确不可用，原配对不被关闭。
- unknown hook、导航和会话变化都不误投。

## 失败与停止条件

不能把一个global布尔值当配对授权，也不能默默回退裸/api。

本轮只完成本任务及其直接验证/局部修复。达到验收、出现具体阻断，或到达需要拆分的范围边界时，写入轮次记录与检查点并结束；不得转入下一任务。缺少 Windows 实机仅影响独立系统验收，不是跳过开发实现的理由。
