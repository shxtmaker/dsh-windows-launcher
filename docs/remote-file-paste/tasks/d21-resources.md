# D21 · 验证背压与资源清理边界

轨道：DEV。状态以 `../execution/state.json` 为唯一真值；本任务卡不预置通过结果。

依赖：D19、D20。默认下一建议：D22（仅建议，不在同轮自动执行）。

## 单一目标

证明可移植路径的内存、队列、缓冲与清理规则有可测上限。

## 允许改动范围

- `Core/JS资源测试`
- `Linux资源采样`
- `平台清理策略`

## 执行步骤

1. 冻结限额与采样方式；最大文件/批次、连续30轮、慢ACK、暂停消费者和取消。
2. 验证2块窗口、全局并发、去重缓存过期、buffer/Blob引用释放与子进程结束。
3. 测试Core清理所有权策略；Windows文件锁/ACL及原生全进程树资源留专项。

## 必须交付

- 参数与资源采样报告、阈值判定、失败回收测试。

## 本任务验收

- 不靠无限队列追求速度；连续操作后保留资源无单调无界增长。
- 每个计量项有明确单位、采样点、通过阈值和实测结果。

## 失败与停止条件

只降低产品限额须同步caps/文档/测试，不切到未验证handle绕过失败。

本轮只完成本任务及其直接验证/局部修复。达到验收、出现具体阻断，或到达需要拆分的范围边界时，写入轮次记录与检查点并结束；不得转入下一任务。缺少 Windows 实机仅影响独立系统验收，不是跳过开发实现的理由。

## 轮末证据与恢复点

记录变更文件、实际命令/退出码/用例数、证据路径与被测候选摘要；列出未验项及所属轨道。状态为 partial/blocked 时写明已保留成果、剩余一步和解除条件；下一轮先核对工作树及进程再恢复。
