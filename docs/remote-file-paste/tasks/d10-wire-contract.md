# D10 · 冻结批次与文件协议并实现双端 codec

轨道：DEV。状态以 `../execution/state.json` 为唯一真值；本任务卡不预置通过结果。

依赖：D02、D09。默认下一建议：D11（仅建议，不在同轮自动执行）。

## 单一目标

明确批次、文件、传输ACK与草稿ACK，生成C#/TS可互读的真实契约。

## 允许改动范围

- `schemas/remote-attachments/`
- `Core/Attachments 协议模型`
- `插件 shared codec`

## 执行步骤

1. 固定 operationId=batchId、独立 fileId、sessionId 与双 epoch 关系，逐文件重置 seq，区分 file-end 与 batch-end，遵守主方案 4.2 节。
2. 固定错误码、最大消息、计数、超时、重放缓存和回收；明确部分成功与重试不重导成功项。
3. 实现生产codec和双方生成/读取的黄金与恶意样本。

## 必须交付

- 版本1 schema、样本、C#/TS codecs与测试。

## 本任务验收

- 整数边界、编码、大小写、重复end和跨文件消息行为一致。
- 传输ack只代表接收缓存，staged只代表草稿接收，ready/发送仍由Harness管理。

## 失败与停止条件

协议模糊先修契约，不让两端各自猜字段或用测试代码复制生产codec。

本轮只完成本任务及其直接验证/局部修复。达到验收、出现具体阻断，或到达需要拆分的范围边界时，写入轮次记录与检查点并结束；不得转入下一任务。缺少 Windows 实机仅影响独立系统验收，不是跳过开发实现的理由。
