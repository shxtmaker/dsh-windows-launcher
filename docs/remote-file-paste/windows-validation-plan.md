# 远程文件粘贴 Windows 实机验证方案

方案版本：2.0。状态：待实现后的执行方案，尚未执行本文任何安装、剪贴板、上传或故障注入验证。编制日期：2026-09-13。

## 1. 验证范围与交接规则

固定部署形态为 **DeepSeek Harness＋`dsh-web-all` 全家桶＋单独安装的附件附加插件**。配对、设备认证和 `/remote` 代理由全家桶中已有的远程访问模块提供，不再重复安装第二份配对插件。附件插件复用 Harness 的草稿、上传 receipt 和发送语义。

开发阶段在 Linux 完成可移植核心、浏览器适配器、协议、真实 Harness 与全家桶集成验证，并交付完整 Windows 薄适配代码。Linux 还应尝试完整项目交叉编译：工具链支持时必须通过；确认属于平台工具链限制时记录边界，普通源码编译错误不能豁免，不能转为依赖 Windows runner 才交付开发结果。具体要求见 [非 Windows 开发验证方案](portable-validation-plan.md)。

本文单独验证完整 solution 的 Windows 原生构建、Windows 剪贴板、WPF 输入、WebView2、实际安装产物和 Windows 资源行为。没有 Windows 环境时，开发工作继续：Linux 项目开发门禁与交接完整可记 `DevelopmentReady`，本文未验部分另记 `WindowsPending`；不得伪造 Windows `PASS`，也不得用 Linux 浏览器测试替代 WebView2 实机证据。本文及正式工程发布门禁全部通过后才可记 `ReleaseReady`。

首期正式数据通路固定为：

```text
Windows 用户粘贴动作
  → 受控文件快照
  → 带序号、ACK、限额和背压的分块 WebMessage
  → 页面构造 File
  → 附件插件适配器
  → Harness 原有草稿与上传流程
  → 全家桶 /remote 认证代理
  → 原会话的待发送附件
```

截图优先保留浏览器原生图片粘贴；原生路径不适用且当前版本明确支持回退时，才由本机桥编码 PNG。每次用户动作只能有一个消费者。只读文件 handle 属于后续优化，不是本次通过条件，不得因其在 HTTP LAN 不可用阻塞分块方案，也不得开启不安全 origin 参数规避限制。

本文用例是新增附件功能的专项验收，不能替代既有 `RS-01` 至 `RS-15` 发布门禁。实现阶段应将新增用例与既有验证影响标签关联，并维护固定测试清单，不得通过删除现有门禁使候选通过。

## 3. 测试环境与版本矩阵

### 3.1 Windows 主机

以候选提交的 `eng/release-constants.json` 为支持范围依据。编制时该文件声明 Windows 11 25H2+ x64 为支持环境、Windows 10 22H2 x64 为兼容记录环境；编制时 WebView2 NuGet SDK 为 `1.0.4129.50`。以上是仓库配置，不是已验证的最低 Runtime 或本次测试机事实。

| 环境 ID | 配置 | 执行范围 |
| --- | --- | --- |
| W11-P | Windows 11 支持版本实体机、标准用户、SSD；资源基准使用 4 逻辑处理器、8 GiB 内存 | 全部附件功能、隔离、权限、30 分钟资源测试 |
| W11-V | 可恢复快照的干净 Windows 11 VM、独立标准用户 | 正式构建、Offline/Online 安装、Runtime 缺失/旧版/损坏、卸载、回退 |
| W11-DPI | W11-P，100%/150%/200% DPI；至少两个不同缩放的显示器 | 输入焦点、菜单、进度/错误可见性、跨屏、键盘回归 |
| W10-C | Windows 10 22H2 x64 实体机或独立 VM | `RECORD` 兼容性结果；共同的数据泄漏、错投、损坏仍判 `FAIL` |

记录 OS 完整构建号、架构、CPU/内存、磁盘类型与可用空间、PowerShell 和 .NET SDK 版本、Launcher 文件版本/提交、WebView2 SDK 及实际 Runtime 完整版本、显示缩放和网络类型。实际 Runtime 从运行中的 WebView2 或既有发布冒烟采集结果获取，不能用 Edge 版本推定。

构建与完整自动测试主机还需准备固定 Node、pnpm、Playwright Chromium 及真实 Harness/all 测试夹具，以运行开发阶段登记的 Core.Tests 生产互操作用例。锁定版本与 Linux 交接一致，清单明确 Core/Interop 用例的并集；缺少工具应报环境未就绪，不能在 Windows 全量门禁静默跳过新增用例。这些工具只用于测试，不成为 Launcher 安装用户的运行依赖。

至少覆盖安装器认定的最低合格 Runtime 与验证当日已固定版本的 Evergreen Runtime。最低版本尚无真实通过证据时，不得宣称已支持；先固定验证候选并记录结果。Runtime 缺失、旧版和损坏的安装测试只在隔离 VM 快照执行，不调整日常开发机 Runtime。

### 3.2 远端与网络

使用 Linux 测试主机 A/B、独立 Harness profile、独立工作区及合成数据。保留 profile 恢复快照。记录实际全家桶配置及加载顺序，确认远程模块只加载一次，附件插件加载一次，原始源码与构建产物身份一致。

| 目标 | 地址与模式 | 必测内容 |
| --- | --- | --- |
| A-LAN | 私有局域网非 loopback 的 HTTP origin | 普通文件、截图、分块、配对、完整发送闭环；localhost 不能代替 |
| A-TLS | 正常可信证书的 HTTPS origin，按实际部署经过反向代理或隧道 | 同一用例、CSP、请求体限制、连接中断 |
| B | 与 A 不同的独立 Harness 实例/profile | 设备凭据、草稿、临时文件、上传和取消互不串扰 |
| A/B 扩展目标 | 按现有 RS-06/RS-13 要求建立共四个不同目标 | 现有目标去重/隔离及 30 分钟混合使用 |

分别验证 Cookie 配对模式与免 Cookie 设备凭据模式。免 Cookie 使用独立测试 UDF/设备或测试专用会话，按已交付协议创建合法连接；不得复制生产凭据。证据只记录认证模式、对应头是否存在、来源是否正确，不写设备密钥、完整配对 URL、Cookie 值或请求正文。若某种模式不适用于候选部署，必须注明协议依据；功能宣称覆盖的模式不能标 `N/A`。

## 4. 合成测试数据

在专用测试目录创建以下数据；使用资源管理器真实复制文件。每项预先记录文件展示名、字节数和 SHA-256，可使用现有 PowerShell 命令：

```powershell
Get-FileHash -LiteralPath 'C:\dsh-paste-validation\fixtures\中文 空格.txt' -Algorithm SHA256
```

目录是执行时创建的测试资产，并非仓库已提供的夹具。哈希清单中的文件名可使用合成名称，证据不保存用户真实目录。

| 数据 ID | 数据内容 | 用途 |
| --- | --- | --- |
| F01 | UTF-8 文本，包含唯一可搜索标识和多行中文 | 单文件及 Harness 工具实际读取 |
| F02 | 0 字节文件；无扩展名文件；Unicode、空格、多点号文件名 | 文件名、空内容、MIME 与展示语义 |
| F03 | PNG/JPEG 文件及相同基名、不同内容的两个文件 | FileDrop 图片、重复名称、内容一致性 |
| F04 | 可重复生成的二进制文件，覆盖 256 KiB 前后边界 | 分块序号、尾块、大小、哈希 |
| F05 | 单文件限额减 1、等于限额、超 1 字节；批次/项数同样三档 | 边界拒绝与部分成功规则 |
| F06 | 足够长的本地路径、只读文件、占用文件、复制后删除文件 | Windows 文件访问及错误提示 |
| F07 | 测试专用目录、UNC 路径、重解析点/Shell 虚拟附件、云盘占位文件 | 首期不支持或受限来源拒绝；不触发云文件自动下载 |
| I01 | 用系统截图工具截取含唯一标识、彩色块、细线的小图 | 原生截图、透明度/色彩、单一消费 |
| I02 | 测试位图夹具填充的透明图及像素上限边界位图 | PNG 回退、透明通道、解码限额 |
| T01 | 普通文本、带换行文本、文本与图片共同出现的剪贴板格式 | 文本回归及格式优先级 |

`CF_HDROP` 只保存文件路径列表。资源管理器复制后、实际粘贴前修改文件，不保证发送复制时的旧内容。验证应以粘贴时捕获的稳定快照为准；暂存过程中源文件变化必须失败或取得可证明一致的快照，不能产生混合字节。

候选交接材料须给出最终限额。若仍采用初始建议值，分别为单文件 20 MiB、单批 10 项/50 MiB、截图编码前 40 百万像素、单目标暂存 100 MiB；有效限额还须取 Harness、模型图片能力和代理限制中的较小值。首期分块建议 256 KiB、最多两块在途，必须从诊断数据核实实际配置。本文测试使用参数化限额，不替代产品限额决定。

## 5. 执行步骤与通过标准

每个用例记录 `PASS / FAIL / BLOCKED / PENDING / N/A / RECORD`。`N/A` 必须附明确的支持范围依据，不能用于跳过宣称支持的行为。错误提示截图、相关日志和请求证据使用同一脱敏 operation ID 关联。

### 5.1 W-01：安装前身份与基线

1. 收齐第 2 节材料并核对提交、插件包摘要和锁文件。
2. 在隔离 Windows runner 运行既有 `pwsh -File .\eng\verify.ps1`；精确 SDK 路径按当前 `eng/README.md` 使用 `-DotNetPath` 指定。该入口必须对完整 `DshWindowsLauncher.slnx` 执行 locked restore、Windows 原生 Release `win-x64` 构建和全部原生测试，不能只构建 Core。保存完整输出及 `verify-summary.json`，必须绑定本次候选提交。
3. 若 Linux 开发已调整多目标框架或增加项目，确认 Windows 门禁同步认识新图谱、锁文件、测试清单和触发标签。任何旧假设导致失败需修复后重跑，不得临时删门禁。
4. 按第 7 节生成正式候选，在安装后的 EXE 中完成后续测试。
5. 记录功能关闭时的配对、打开远程 UI、文本粘贴、流式回复、标签切换基线；启用附件功能后逐项对照。

通过标准：同一提交的 Windows 工程门禁 `PASS`；安装产物身份可核对；功能关闭/启用不破坏现有远程流程。未执行 Windows 构建时，本项保持 `PENDING`，不影响 Linux 开发完成状态。

### 5.2 W-02：普通文件、截图与输入所有权

| 用例 | 操作步骤 | 通过标准 |
| --- | --- | --- |
| W-02.1 单文件 | 在 A-LAN 现有会话输入框定位光标，资源管理器复制 F01，Ctrl+V | 恰好一个待发送附件；输入框不插入 Windows 路径；无自动发送 |
| W-02.2 多文件 | 复制 F01～F04 的合规组合，一次粘贴 | 文件名称、大小和数量正确；同名不同内容文件不会相互覆盖或错误去重 |
| W-02.3 边界数据 | 依次粘贴 F02、F04、F05 | 空文件和尾块正确；超过限额在字节交付前明确拒绝；成功项不要求重复上传 |
| W-02.4 截图 | 用系统截图工具复制 I01，回到编辑器 Ctrl+V；重复 10 次，逐次移除 | 每个动作仅创建一个图片附件；原生路径与桥无双重导入；未主动发送前无消息 |
| W-02.5 图片格式竞争 | 复制 PNG 文件，使 FileDrop 与图片格式并存；再复制只有位图的 I02 | 文件列表按已确定优先级单次处理；位图回退只在协商允许时发生，无重复图片 |
| W-02.6 文本与组合格式 | 粘贴 T01，包含文本与图片共存的场景 | 普通文本保留原生语义；混合格式遵守已公布规则，不重复文字或吞掉输入 |
| W-02.7 快捷键/菜单 | 在焦点正确时测试 Ctrl+V、Shift+Insert、网页右键粘贴、已实现的“粘贴附件”入口 | 产品承诺的入口都可用；未承诺入口不能触发越权或重复；文档准确列明支持入口 |
| W-02.8 焦点与 DPI | 在搜索框、设置框、非编辑器区域粘贴；100%/150%/200% 下跨屏切换后重测 | 不读取或上传文件；文本控件正常；附件提示、取消按钮和焦点可见且可键盘操作 |

截图允许 Harness 依其图片能力做规范化或缩放。需要分别保存本机生成/浏览器接收字节的一致性证据，以及 Harness 最终图片的维度、可见标识和工具/模型输入证据；不得把规范化后哈希不同直接判为传输损坏，也不得仅凭缩略图证明成功。

### 5.3 W-03：真实上传与主动发送闭环

对 A-LAN、A-TLS 以及各自需要支持的 Cookie/免 Cookie 模式分别执行：

1. 粘贴 F01 和 F04。观察附件由上传中进入可发送状态，捕获实际上传路径、认证模式、状态码和脱敏业务 envelope。
2. 确认普通文件经过对应目标的 `/remote` 认证上传路径。检查没有 Worker XHR 绕过代理的 `/api/session/uploadFileBinary` 未认证请求，也没有二次 `/remote/remote` 改写。
3. 保存本机快照 SHA-256、页面构造 File 的字节数/哈希、远端受控工具读取文件的字节数/哈希，三者必须一致。检查文件 receipt 对应原会话。
4. 主动发送消息，明确要求 Harness 使用文件工具读取 F01 的唯一标识并核对 F04 哈希。记录工具实际读取结果及只读工具路径映射，不以模型猜测文件名作为证据。
5. 粘贴 I01 并主动发送。确认最终消息包含图像输入，唯一标识/图形可正确识别，且没有重复图片或额外空消息。
6. 再粘贴并移除附件；确认移除后主动发送不包含该附件。检查本功能仅回收其本机暂存，不删除 Harness 内容寻址的共享对象。

通过标准：待发送附件、真实字节、原会话 receipt 和主动发送后的实际读取四项全部成立；HTTP 200 内含 `{ok:false}` 时必须显示失败。没有文件工具或容器工具路径不可读属于真实集成失败，不能记为上传成功。

### 5.4 W-04：草稿、页面与目标隔离

在 A 创建会话 A1/A2，在 B 创建 B1，准备含不同标识的文件。每次变更前后记录 target/document generation/draft/session 的脱敏对应关系。

| 用例 | 操作步骤 | 通过标准 |
| --- | --- | --- |
| W-04.1 新草稿 | 分别在已有 sessionId 但尚未发送消息的新会话，以及尚未选择工作区/没有 sessionId 的首页粘贴 | 前者与已有会话一致，可加入待发送附件；后者明确提示先建立会话再粘贴，不上传、不自动建会话、不暗中暂存后投递；建立会话重新粘贴应成功 |
| W-04.2 切会话 | 在 A1 暂存/分块过程中切 A2，随后等待迟到 ACK、导入结果和网络响应 | 原操作按契约取消或仅保留已归属 A1 的附件；A2 不出现附件；不得改投当前会话 |
| W-04.3 多目标 | A1/B1 同时导入不同文件，切标签并取消 A 的操作 | B 不受影响；凭据、文件、错误、取消和日志关联正确；没有串目标 |
| W-04.4 新建/删除草稿 | 导入中删除原草稿、创建新草稿，模拟迟到结果 | 新草稿不继承旧附件；旧 operation ID 不能恢复；无自动发送 |
| W-04.5 隐藏窗口 | 在途时关闭远程窗口使其隐藏，然后尝试页面请求；再打开 | 隐藏时不能创建新操作；已开始操作按交付契约完成到原草稿或取消，不转移目标；重开不重放 |
| W-04.6 导航/刷新 | 暂存、分块、导入各阶段刷新、后退、重定向或关闭标签 | 导航开始使旧桥失效；新文档重新握手；迟到 ACK/结果不可作用于新文档 |
| W-04.7 删除目标 | 在途时忘记测试目标，随后重新添加 | 操作取消，暂存按策略清理；其他目标不受影响；新目标不恢复旧导入 |
| W-04.8 不支持会话 | 在子代理会话或适配器不支持的 composer 尝试普通文件粘贴 | 提前明确不支持；不创建孤立 receipt，不把文件转发到父会话或其他 composer |

### 5.5 W-05：来源、权限与路径边界

用受控测试页/诊断入口及合成路径执行，不在生产页面运行破坏性脚本。

| 用例 | 操作步骤 | 通过标准 |
| --- | --- | --- |
| W-05.1 非用户动作 | 页面发送伪造粘贴请求、`isTrusted` 字段、过期/重复 operation ID | 无原生手势就不读剪贴板或磁盘；不存在网页可调用的通用 `readPath` |
| W-05.2 来源变化 | 在可信页打开外链、改协议/端口/主机、经过跨源重定向，再发送桥消息 | 按规范化 scheme/host/port 校验；外部文档未继承能力；无凭据或文件字节外发 |
| W-05.3 frame 与后台 | 同源和跨源 iframe、后台标签尝试调用桥或请求分块 | 仅授权活动顶层编辑器可开始操作；来源相同不能替代用户动作 |
| W-05.4 非预期消息 | 发送未知类型、畸形 JSON、超大 chunk、错误序号、跨操作 ACK | 有界拒绝并记录脱敏错误；无内存无限增长、崩溃或额外文件读取 |
| W-05.5 本地来源 | 对 F06/F07 分别粘贴；源文件无权访问、只读、共享锁、UNC、目录、重解析点 | 支持项正确处理；未支持来源明确拒绝；不追踪目录、不枚举网络共享、不绕过 ACL |
| W-05.6 快照一致性 | 粘贴前修改源文件；暂存中修改/删除；暂存完成后再次修改 | 捕获时快照语义明确；暂存中变化失败或保证一致；完成后上传不读取变更后的源文件 |
| W-05.7 暂存清理 | 用专用测试暂存目录模拟文件锁、只读、磁盘不足及路径重解析 | 不清理应用根外任何数据；失败可恢复；未解决资源有可观测上限，不能无限重试 |
| W-05.8 诊断与权限 | 导出诊断，核对宿主对象、文件权限、下载及剪贴板行为 | 不新增通用文件系统 host object 或任意网页剪贴板权限；日志无正文、完整本机路径、设备凭据 |

暂存路径测试必须先确认执行目标是专用测试目录，并记录最终绝对路径及所有权检查结果；不得递归清理系统 Temp 或用户真实文件目录。向页面交付过的字节无法收回，取消应停止后续交付和草稿错投，不能声称撤销已分享的数据。

### 5.6 W-06：背压、失败、取消与恢复

使用 Linux 测试反向代理或已交付故障夹具控制响应；记录夹具版本和配置，不假定仓库已有附件专用故障命令。

| 用例 | 操作步骤 | 通过标准 |
| --- | --- | --- |
| W-06.1 背压 | 暂停页面 ACK，随后逐块恢复；重复、延迟及打乱 ACK | 在途块不超过配置上限；无逐消息无限排队；错误序号拒绝；恢复不重复导入 |
| W-06.2 断网/超时 | 在分块前、上传中、返回 receipt 前分别断网，恢复后观察并手动重试 | 明确失败/可重试；不自动发送；不确定成功请求不盲目重复创建附件；成功项不重复 |
| W-06.3 业务拒绝 | 注入 413、401、403、5xx、HTTP 200 `{ok:false}` 和畸形响应 | 区分限制、配对失效和上传失败；无卡死 uploading、假 ready 或静默丢失 |
| W-06.4 本地取消 | 在捕获、暂存、分块、导入/上传阶段分别取消 | 停止后续本机读取/交付，原草稿状态可解释；迟到结果不复活操作 |
| W-06.5 吊销配对 | 上传过程中在测试全家桶管理界面吊销设备 | 后续请求失效并取消本机操作；其他设备/目标正常；已分享字节不宣称可追溯收回 |
| W-06.6 Harness 重启 | 文件 ready、尚未发送时重启测试 Harness，再尝试发送 | 旧内存 receipt 不视为永久有效；提示重新添加/上传；不发送不可读路径或自动重发消息 |
| W-06.7 Renderer/App 重启 | 用测试环境故障方法终止对应 renderer，再终止 Launcher；分别重开 | 孤立操作不重放，暂存按启动清理策略回收，配对与目标数据保留 |
| W-06.8 插件失配 | 用已知不支持版本或关闭附件插件打开远程 UI | 能力握手失败时禁用桥并提示原因；原生文本、既有图片能力与配对继续可用 |
| W-06.9 全家桶升级/停用附加插件 | 在测试快照中升级到待支持版本；单独停用附件插件后复测 | 适配器探测准确；不重复安装远程模块；停用附加插件无需停止基础配对服务 |

取消后“未收到任何字节”只适用于取消发生在交付前的用例。在途网络请求可能已被远端接受，应单独记录服务端结果及草稿归属；安全通过条件是后续能力失效、无错投、无重复发送和资源有界。

### 5.7 W-07：响应性、内存与磁盘

1. 使用 W11-P 资源基准配置，记录无附件时 5 分钟基线。采样覆盖 Launcher 及其 WebView2 子进程树，不能只看 WPF 主进程。
2. 对小文件、接近单文件上限、合规最大批次分别执行至少 10 轮；每轮等待完成并移除附件。记录捕获、暂存、分块、导入、远端 ready 耗时、峰值 Private Bytes、原生暂存字节和上传并发。
3. 对满批传输暂停 ACK 30 秒，确认峰值不随暂停时间持续增加。单块 Base64 开销、页面完整 Blob/File 和截图解码占用都须计入结果。
4. 全家桶四目标混合使用 30 分钟，最后 5 分钟稳定空闲，执行现有 RS-13；附件操作作为前 25 分钟混合负载的一部分。
5. 在正常结束、取消、导航、Renderer 退出和 Launcher 崩溃恢复后检查暂存；活动引用期间不得提前删除，释放后按已交付清理时限回收。
6. 在上传中切标签、输入一行文本、点击取消并录屏；核对没有持续 UI 冻结、焦点跳转或按钮不可操作。

当前 RS-13 源码阈值为进程树峰值 Private Bytes 不超过 2.5 GiB、最后 5 分钟平均 CPU 不超过 10%、正常退出后四个 UDF 锁在 60 秒内释放。候选若调整阈值，必须提供理由并同步正式门禁，不能仅在本附录放宽。

附件专项增加以下可执行判定：在固定同一负载下，后五轮操作结束并空闲后的内存不得逐轮保持增长，最后一轮相对首轮稳定值的差额不得超过 `max(100 MiB, 首轮稳定值的 20%)`；每轮比对使用相同等待时长，初始设为 60 秒。专用暂存不超过配置总量，所有无活动引用的文件在承诺清理时限内回收；若未给清理时限，交接不完整。取消后 2 秒内停止新 chunk 发送，阻塞中的文件 IO 单独记录其取消完成时延。普通键盘输入和取消按钮不得连续 1 秒以上无响应。这些是首期建议验收阈值，首次正式执行前由候选契约冻结，不得在失败后无依据放宽。

吞吐率仅作同环境对比记录，不用合成 Windows 数据推定远端 Linux 性能。性能失败可降低限额、并发或优化拷贝，再针对相关用例复测；不得以切换到尚未验证的 handle 路径绕过失败。

## 7. Offline/Online 安装、升级与回退

### 7.1 正式打包

在未安装本产品的干净隔离 Windows runner 上执行当前 `eng/README.md` 定义的正式入口。必须保留 `installer/DshWindowsLauncher.iss` 的安装保护；不得替换为 `package-unsigned.ps1` 或轻量内部包。

执行者先设置候选版本和经过验证的输入路径，再调用已有参数。下面是执行模板，尖括号内容必须替换；此处没有执行授权或运行结果：

```powershell
$candidateVersion = '<与候选 release-constants 完全一致的版本>'
$webViewOffline = '<冻结的 WebView2 Standalone x64 安装器绝对路径>'
$webViewBootstrapper = '<冻结的 WebView2 Bootstrapper 绝对路径>'
$innoInstaller = '<冻结的 Inno Setup 官方安装包绝对路径>'
$innoCompiler = '<ISCC.exe 绝对路径>'
$offlineVerificationDirectory = '<隔离固定卷上的专用空目录>'
$onlineVerificationDirectory = '<另一个隔离固定卷上的专用空目录>'

pwsh -File .\eng\package.ps1 -Version $candidateVersion -PackageMode Offline -WebView2OfflineInstallerPath $webViewOffline -WebView2BootstrapperPath $webViewBootstrapper -InnoSetupInstallerPath $innoInstaller -InnoCompilerPath $innoCompiler -UninstallerVerificationDirectory $offlineVerificationDirectory -AllowInstallerExecutionForUninstallerVerification

pwsh -File .\eng\package.ps1 -Version $candidateVersion -PackageMode Online -WebView2BootstrapperPath $webViewBootstrapper -InnoSetupInstallerPath $innoInstaller -InnoCompilerPath $innoCompiler -UninstallerVerificationDirectory $onlineVerificationDirectory -AllowInstallerExecutionForUninstallerVerification
```

该既有脚本会运行正式验证并实际短暂安装/卸载以验证卸载器。只能由已获相应安装验证授权的执行者在隔离 runner 执行；本方案编制不意味着已执行或可更改日常机器。输入版本与摘要以候选冻结常量为准，不能复用未经核对的旧版路径。

Offline、Online 产物分别保存自己的安装包、清单、SHA-256、验证摘要、SBOM、第三方许可证和安装/卸载证据。核对候选 EXE、实际已安装 EXE、托管程序集、Bootstrapper 及卸载器身份；现行策略要求自有产物 `NotSigned`，第三方输入签名有效。

### 7.2 实际安装矩阵

| 用例 | 操作 | 通过标准 |
| --- | --- | --- |
| W-08.1 Offline 全新安装 | 完全断网、Runtime 缺失的干净 VM，以标准用户安装 | 随包 Runtime 修复成功，无不必要提权；开始菜单/卸载登记正确；安装后 A-LAN 文件＋截图闭环通过 |
| W-08.2 Online 全新安装 | 网络正常、Runtime 缺失快照安装 Online | 经过冻结 Bootstrapper 安装合格 Runtime；附件闭环与 Offline 相同 |
| W-08.3 Runtime 异常 | 缺失、低于下限、损坏、健康快照分别安装两类包 | 检测/修复/复检正确；健康 Runtime 复用；失败前不覆盖程序文件 |

| W-08.7 安装路径 | 默认目录及合格空固定卷目录安装；拒绝危险目录和重解析路径 | 维持现有安装保护，无路径逃逸或覆盖无关文件 |

修改全家桶 `enabled=false` 或停用远程模块可能影响设备状态，不能把它当作仅关闭附件的常规回退。首选附件功能开关、停用附加插件或发布修复版本；仅测试环境可恢复隔离快照，恢复后需重新核对设备状态，不能恢复会复活已吊销设备的旧凭据快照。生产远端更新和 Launcher 发布均是后续独立操作，不属于编制/开发验证的默认动作。
