## 2. 组合结构（验收点：不在事件处理器里重写状态机）

`RemoteAttachmentBridge` 是 `RemotePageSession` 的**组件**而非第二个生命周期：`InitializeAsync` → `AttachTo(core)`；导航 → `OnPageAdvanced()`、能力授予 → `OnMainDocumentLoaded()`、关闭 → `Close("session-closed")`、释放 → `Dispose()`，全部由页面会话驱动。

**转发复用 Core**：出站帧仍由 `AttachmentCodec` 构造校验 + D10 镜像状态机判定；入站封包过同一 codec 后交给 D11 `Pump()`——事件处理器内**没有第二套状态机**。

**每次收发复核身份与大小**：出站复核 session/target/双 epoch 与 512 KiB 上界（`context-changed`/`message-too-large`）；入站依次复核封包大小 → 结构 → 页面准入（通道/代际/能力，复用 D15 `AdmitMessage`）→ 帧身份。入站队列有硬上界，`WebViewMessageTransport` 把两种投递形态归一。

## 3. 握手接通（闭合 D16 登记的缺口）

`RemoteBridgeHandshake` 真实解析 `hello`（对端 build）、`capabilities`（features → `ScreenshotOwnerFacts`，限额逐项 min 钳制）、`context`（身份 + composer 事实），经 `IRemoteBridgeHandshakeSink` 送进 **D16 的真实台账**。因此模式判定可用：页面声明 `screenshot` 且宿主原生采集可用 → `native-paste`；未声明或宿主无采集 → `bridge`；**握手到达前仍 `undecided`**（位图粘贴继续确定拒绝）。Linux 用真实 D16 编排器逐段断言这三段路由。

## 4. 取消 / 迟到 / 释放 / 心跳

- 主动取消：发 `cancel`、停后续传输、释放源与快照；迟到 `ack`/`import-result` 得 `cancelled`/`batch-closed`（不静默）。
- 导航 `Invalidate()`（不发帧）并推进代际，迟到帧 `message-epoch-stale`；目标删除/吊销/退出 `Close()` → `session-closed`。
- 暂存快照在批终态/取消/失败/导航/关闭/释放**每个出口**都 `Release`；通道监听、入站队列、`DispatcherTimer`、句柄各有归零断言。
- **心跳不受影响（可移植证据）**：真实 `PairingHub`（真实保活循环 + 内存目标库）与完整桥生命周期并排跑，断言枢纽配对待定字段不变、`IsStarted` 仍真、心跳计数继续增长、`HeartbeatNowAsync` 仍成功；另有结构性护栏：桥的公开表面**不含任何配对/枢纽成员**。实机用例 WB-06 登记待验。
