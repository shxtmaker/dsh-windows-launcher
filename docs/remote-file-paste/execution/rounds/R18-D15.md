## 2. 来源与身份规则（验收点）

规范化：仅 http/https、scheme 小写、默认端口省略、主机小写并去结尾根点、IPv6 字面量经 `IPAddress` 规范化后加括号、**userinfo 一律拒绝**；比较只做规范化后**逐字相等**，绝无前后缀匹配。已跑的负例：`http://evil.example@our.host/` → `origin-userinfo-rejected`；`our.host.evil.example` / `evil-our.host` / `our.hostx` / `sub.our.host` / 异端口 / 异协议 → 外部；`file:`/`about:`/`javascript:`/`data:`/`//host` → 不支持协议；`our.host%2Eevil.example` → invalid。

**一条实测发现**：.NET `Uri` 会把 `http://[::1].evil.example/` 的 Host 解析成 `[::1]` 并**丢掉后缀**（若只信 `Uri.Host` 就会被绕过）。已改为对照原始 authority 文本复核，并补了专门负例（`http://[::1]evil.example/`、`[::1]:`、非数字端口同理）。

主文档规则：只有 `MainDocument` 能授予能力；子框架/子资源**既不授予也不撤销**；**外部链接一律不继承**文件能力；重定向只认最终文档 URL。

## 3. epoch 与迟到消息

`BeginNavigation` 在**主文档导航开始当刻**：撤销能力（`capability-revoked-navigation`）、取消旧代际令牌、`Epoch+1`。`CompleteMainDocumentLoad` 仅在最终文档来源逐字相同且本次非外部链接导航时按当前代际授予。`AdmitMessage` 判定顺序固定（关闭 → 通道 → 代际 → 能力）：旧代际迟到消息 `message-epoch-stale`、未验证文档 `message-capability-absent`、跨页面通道 `message-channel-mismatch`、已关闭会话 `session-closed`。

## 4. 取消触发

`NavigationStarted`＝取消旧代际在途工作＋立即撤销能力（新文档重新验证后才恢复）；`TargetRemoved`／`CredentialRevoked`（快照检测到 `Pairing!=Paired`，与"目标不存在"分开记录）／`ApplicationExit`（窗口 `Closed`→`Detach`、`AllowClose` 关闭）＝关闭会话、取消在途，之后一律 `session-closed`。隐藏/切标签按方案只拒绝**新**操作（`work-page-suspended`），不取消在途、不提代际。

## 7. 需要 Windows 轮次处理的一处**数据集隐患**（本轮仅报告、未改）

`Platform.Windows.Tests` 有 **4 条含反斜杠参数的理论用例**：MTP 的 XML 输出会把 `\` 再转义为 `\\`，而 D14 建立的该程序集基线来自**枚举 JSON** 的归一值。因此在真实 Windows 上跑 XML 门禁时，这 4 条会报 `missing/unexpected`。修正它会**删除既有基线哈希**，按"无既有哈希消失"的规则本轮 STOP 未动。**处理建议**：在 Windows 轮次用真实 XML 重新推导该程序集基线（届时该程序集本就能执行），或统一两处的转义归一规则；在此之前不要声称该程序集的基线在 Windows 上可用。
