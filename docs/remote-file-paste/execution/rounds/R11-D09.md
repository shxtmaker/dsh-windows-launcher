## 2. 闸门发现的产品缺陷（本轮最重要产出）

**D09 首次运行 6/11：文本附件上传必然失败，而 D07 全绿拦不住它。**

- 现象：文本附件导入后 composer 芯片停在「重试上传 d09-note.txt」，发送按钮因 `uploadsPending` 永久禁用，**网络层 0 条上传请求**。（PNG 不受影响：图片不走上传，浏览器内联 base64。）
- 根因：`src/host/upload-hook.ts` 把 `__DSH_FILE_UPLOAD__` 装成**裸函数**，而锁定版本的消费者读的是 `hook.fetch`：

  ```js
  // @deepseek-ai/dsh-client-file-upload@0.1.5-rc.2/lib/client.js:161
  this.transport = hook === void 0 ? workerTransport() : customTransport(hook.fetch);
  ```

  该包 README 写的是 "supply a **Fetch-shaped carrier** before Cordis boots"。裸函数 → `customTransport(undefined)` → 文本上传 TypeError。实测 `typeof hook='function'`、`hook.fetch='undefined'`。
- **为什么既有门禁没拦住**：`tests/fixtures/upload-gates.mjs` 的 U03 断言写的是 `typeof hook === 'function'`——把错误契约固化成了判据，于是 D07 全绿。这是"D07 判据本身写错"的教训，与 R09 的 F05 只查骨架属同一类：**判据断言了实现，而不是断言上游契约**。
- 最小修复（本轮实施，属任务卡允许的"直接验证/局部修复"）：
  1. `src/host/upload-hook.ts`：改为安装 fetch 形状 `w[G]={fetch:carrier}`（`carrier` 仍是原函数，仍在**调用时**读 `w.fetch`，不提前捕获裸 fetch），并在注释里写明锁定契约与消费者行号；
  2. `tests/fixtures/upload-gates.mjs`：U03 改断言 `typeof hook === 'object' && typeof hook.fetch === 'function'`，三处直接调用改 `hook.fetch(...)`，探针增加 `hookFetch`；
  3. `test/unit/upload-hook.test.mjs`：新增"装成 fetch 形状"判据；"调用时才读 fetch"改为断言**安装点之后不再出现 `w.fetch`**（比原来更强）。
- 修复后：闭环 13/13（本报告 §1 的实测值即修复后的产品路径）。
