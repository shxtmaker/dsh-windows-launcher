## 2. 验收点的实测结论

- **只接受原生用户动作捕获的普通文件**：拒绝顺序固定（先对象种类：目录→`candidate-directory`、设备/管道→`candidate-not-regular-file`；再路径形态：UNC→`candidate-unc-path`、`\\?\`/`\\.\`/`\??\`→`candidate-device-path`、非绝对→`candidate-path-not-absolute`、含 `..`→`candidate-path-traversal`；再属性：重解析点→`candidate-reparse-point`、云占位→`candidate-cloud-placeholder`、离线→`candidate-offline-file`、远程卷→`candidate-network-share`）。打开一律带 `FILE_FLAG_OPEN_REPARSE_POINT`，**链接不会被跟随**。
- **受控快照**：限额判定（单文件 → 批文件数 → 批字节 → 单目标 100 MiB → 可用空间留 64 MiB）全部发生在 `CreateExclusiveOwnedFile` **之前**；提前 EOF、声明外增长、复制后长度/最后写入时间/文件标识/卷任一处不符 → `source-changed` 并删除半成品。
- **只清理自有目录**：清理只接受台账 id 或自有根一层条目；词法包含关系（拒穿越/绝对/UNC/根相对）+ 平台解析后最终路径 + 重解析点/目录复核；Linux 侧用假端口**真实跑通**这些拒绝分支（含 symlink 逃逸、`..\..\Windows\evil.dll`、UNC、目录、删除失败）。
- **没有任意远端路径读取入口**：引擎唯一快照入口是 `Capture(INativeStagingCapture, CancellationToken)`；适配器公开成员只有 `BeginBatch`/`CaptureForBridge`/`Release`/`CleanupOrphans`/`Initialize`；Linux 与 Windows 各有一条反射用例钉住该表面。

## 5. 顺带修掉的源码错误

1. **`AttachmentTransferCoordinator.AdmitFile` 准入不校验元数据**（已修）：过去只校验限额，不校验将写进 `file-begin` 的 `fileId`/`name`/`mime`/`sha256`；非法元数据被收下后，直到 `Pump()` 构造 `file-begin` 时才由冻结 codec 抛 `InvalidOperationException`（用临时探针实测到该异常）。修复为 `Wire.FileBegin` 显式字段重载 + 准入处复用同一 codec 预检并返回确定码（`invalid-field-value`/`field-too-large`），新增 9 条回归用例（先红后绿）。
2. **登记未改的观察**：`AttachmentSession` 在批次成功关闭后未清 `file.Sent`（每文件最多 80 条 `SentChunk` 常驻至 `Dispose`），无可观测行为差异，故未改，仅登记待后续处理。
