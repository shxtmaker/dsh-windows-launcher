## 1. 互通结构（只替代 WebView2 边界，不替代 sender 算法）

- **C# → 驱动 stdin**：一行一条**由生产 C# codec 编码的报文 JSON 原文**（无自造信封）。
- **驱动 → C# stdout**：`{"kind":"page"…}`（页面就绪）、`{"kind":"frame","frame":{…}}`（`ack`/`import-result`）、`{"kind":"reject"…}`（接收端拒绝：stage/code/detail）、`{"kind":"done"…}`；stdin EOF = 优雅退出；日志走 stderr。
- **复用（生产实现）**：真实 `AttachmentTransferCoordinator`（分块、2 块在途背压、seq/offset、SHA-256、批次状态机、D10 镜像预校验、去重缓存）+ `AttachmentCodec` + 页面全局 `__DSH_ATTACHMENTS_RECEIVER__`（D12 生产接收端及其状态机）+ `__DSH_ATTACHMENTS_BRIDGE__` → D08 草稿适配器。
- **仅替代三处**：① stdio 通道（WebView2 物理边界）② `context` 握手投递（真实承载层在 hello/capabilities 后回执；帧仍由生产 codec 校验）③ Linux 只读文件短读源（同一 `IAttachmentByteSource` 契约，替代 Windows 暂存句柄）。
- **发送算法是生产的证据**：出站帧全部由协调器经 codec + 镜像后才进通道；trace 中三个 chunk 的边界字节按 seq 拼回后与源文件 SHA-256 相同。驱动**不生成、不改写、不补发**任何业务帧（唯一例外是显式开启的负向探针 wrong-batch-id）。

## 2. 双向证据

`artifacts/verify-portable/d18-interop/<case>.trace.jsonl`（驱动侧双向）、`<case>.csharp-transcript.jsonl`（C# 侧双向）、`<case>.csharp-trace.json`（生产协调器 trace）。

核对结论：**哈希五处一致** —— C# 源文件 = `file-end` 声明值 = 接收端核对值 = trace 重组值 = 浏览器 File 回读（Node 独立计算）。**批次/文件 ID**：每帧 `batchId` 与协调器一致（仅 `context` 握手无 batchId），文件集 `[alpha,beta]` 三方一致。**草稿 ID**：协调器记录 `AttachmentIds` = `import-result` 帧 ids = 页面 `draftAdded`，草稿探针净增 2/2。**ACK**：3 块逐块 seq/offset/长度对上，`AckedBytes=ByteLength`，`PendingBytes/PendingChunks=0`。**import-result**：2/2 `staged`，协调器入站拒绝 0。

## 5. 负向探针

1. **篡改一个字节**（在通道里对 chunk 载荷首字节取反，不改发送算法）：接收端以 `hash-mismatch` 拒绝 `file-end`，未组装 File、无 `import-result`、草稿净增 0，C# 协调器按注入时钟判 `import-timeout` 且批次 `Cancelled`；trace 显示边界字节 sha ≠ 源 sha，而 `file-end` 声明=源 sha。
2. **错误 batchId**（驱动克隆真实 `import-result` 并改 batchId + 假 id）：C# 生产协调器对每一条探针帧以 `import-result:batch-not-open` 拒绝（2/2），假 id 未进入任何记录，真实结果仍 2/2 `staged`。
3. **传输中强杀 Node 子进程**：`exitCode=137`、`killRequested=True`、批次停在 `Open`、文件 `Transferring`、`import-result`/`batch-end`/`done` 记录 0、trace 只到半途；**同一个** clean-exit 判据在正向路径必须为 True 而此处为 False——若被杀却判通过，用例立即失败。
