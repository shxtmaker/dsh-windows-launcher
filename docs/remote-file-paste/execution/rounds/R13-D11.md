## 2. 设计要点

**注入端口（决定测试能否确定性复现）**：`Read(Span<byte>)` 允许**短读**、返回 0 表示 EOF；负值/越界/抛异常 → `source-error`。`Send(json)` 立即返回、`TryReceive` 非阻塞——**没有后台线程、没有定时器、没有 sleep**。`IAttachmentClock.NowMs` 承载全部超时与缓存 TTL，测试用 `ManualClock.Advance` 推进时间。因此乱序、重复、超时、取消都能逐帧可控复现，而不是靠延长 sleep 掩盖竞态（任务卡的失败条件）。

**单一校验来源**：每条出站帧先由冻结的 `AttachmentCodec` 校验，再喂给生产 `AttachmentSession`（D10 镜像），**镜像拒绝的帧绝不发出**；入站 `ack`/`import-result`/`cancel`/`batch-end` 同样由该镜像判定。序号、窗口、幂等与结果校验因此没有第二份实现。

**状态机**：批次 `None→Open→Closed/Cancelled`；文件 `Pending→Transferring→AwaitingImport→Staged/Failed/Partial/Cancelled`。

**D10 规则的落点**：重复 `ack`/`import-result` → 幂等（`importInvocations` 不增）；重复 `batch-end` 与缓存 digest 比对（一致则幂等、冲突则 `duplicate-operation`）；批次关闭后的迟到 `file-end`/`chunk`/`import-result` 一律 `batch-closed`、**0 新帧**、不重开批次；`sessionId` 缺失/不符在镜像 apply **之前**返回 `no-session`/`context-changed`（`AckedBytes` 不变）；`staged` 时写 `epoch:epoch::fileId` 台账，跨批次 `AdmitFile` 命中即 `duplicate-operation`——**已确认成功项永不重导**，重导必须新 `batchId`/`fileId`。

## 3. 上界（任务卡验收「所有待确认字节、队列、缓存都有上界」）

| 对象 | 上界 | 断言位置 |
| --- | --- | --- |
| 待确认字节 | ≤ 512 KiB = `2 × 256 KiB`（只在 in-flight < 2 时读） | `MaxPendingBytes`，多例逐步断言 + trace 记 `observedMax` |
| 队列深度 | ≤ `fileCount`（≤10）/ 闸门等待 ≤ `queueCapacity` | 并发闸门用例 |
| 去重缓存 | `size ≤ max(capacity, pinned) + 1`，`pinned ≤ fileCount + 1`；capacity=4 时断言 `Evicted > 0` 且不随批次数增长 | 缓存有界用例 |
| Scratch | ≤ 256 KiB，`file-end` 后归零 | 逐文件用例 |

`dataBase64` 只对**单块**（`ReadOnlySpan<byte>`，来自 256 KiB scratch）编码，不存在全文件 Base64；无 `System.Windows`/`DllImport`/`Marshal`（已 grep 核实）。

## 6. 未验项与一处需要后续对齐的差异

- **未验**：只验证了 C# 两端（D11 协调器 ↔ D10 `AttachmentSession`）；真实 WebView2/Chromium 的消息边界与 TS 接收端属 D13/D14/D16。通道是进程内接口，未接真实 WebMessage/网络传输。本地码（`source-error`/`ack-timeout`/`import-timeout`/`idle-timeout`/`queue-starved`/`disposed`）**绝不入线协议**，若后续 UI 需要统一码表应另立任务。
- **需要 D12/D13 确认的差异（本轮如实记录，未擅自改 D10）**：D10 的 `AttachmentSession` 在**没有新 `context`** 时拒绝对同一会话的第二个 `batch-begin`（保留 Closed 批次），而协调器允许用新 `batchId` 开新批（镜像按批重建 + 缓存判重）。方案原文支持后者（"批次关闭后新批次必须经 batch-begin 承认"，且重导失败项要生成新 batchId/fileId），因此协调器行为正确；但**若真实接收端直接以 D10 的 `AttachmentSession` 为状态载体，同会话的第二个批次可能被误拒**。D12 落接收端时必须明确：同会话新批次是否需要重发 `context`，并把结论写回 D10 契约（或调整 `AttachmentSession`）。这是当前唯一已知的跨任务语义缺口。
