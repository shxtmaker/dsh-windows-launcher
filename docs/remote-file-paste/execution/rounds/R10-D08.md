## 1. 本轮新增：版本化附件桥（`src/client/bridge.ts`）

适配器（`draft-adapter.ts`）刻意只依赖一个最小外部面，因此"把真实 cordis 服务、会话 scope 与 DOM 接上去"这件事需要一层实现。本轮补上，并在插件挂载时安装为页面全局 `__DSH_ATTACHMENTS_BRIDGE__`（`version: 1`）：

```js
globalThis.__DSH_ATTACHMENTS_BRIDGE__.importFiles({ sessionId?, files }) → DraftImportResult
```

**归属确认（方案 4.4 节要求"不能只做选择器命中"，四道判据）**：

1. 目标会话必须能 `ctx.sessions.scope(sessionId)` 解析出 scope，否则 `no-session`；
2. 必须是**当前会话**（`ctx.sessions.list` 的 `current`）——当前会话是唯一被渲染出 composer 的那个，这条把"可见卡片"钉到会话身份上，不满足即 `context-changed`；
3. 文档内必须**恰好一个** `[data-composer-card]`，多于一个即归属不确定 → `no-composer-card`（宁失败不猜）；
4. 卡片内必须恰好一个 `input[type=file]`（由适配器的 `locateFileInput` 保证），否则 `no-file-input`。

两次实测出来的实现要点：

- **服务必须惰性解析，不能缓存。** 第一版在 `apply` 时取一次 `ctx.get('sessions')` 并保存，结果宿主在 `apply` 期间还没有该服务 → 桥永久失效，真实会话里表现为"会话已打开却报 `unsupported`"。改为每次调用取值的函数后通过。测试为此专门保留了 `getSessions` 形状的单测。
- **`ctx.get` 是合法成员。** 早先为"apply(ctx, config)"写的 cordis 代理桩把所有未知属性都判为违规，把 `ctx.get` 也拦了；`get` 是 cordis 的服务解析入口，必须放行。

## 2. 真实会话的建立方式（独立侦察，全部实测）

会话相关的关键事实**不是**猜的（由独立子代理在夹具上端到端验证）：

- **会话按 `DSH_HOME` 共享、跨 profile 可见**：`<DSH_HOME>/sessions/<slug>/session-<uuid>/session.v3.jsonl.zstd`（zstd JSONL，首行 header）。因此用 `dsh --profile dsh-attachments-headless "<task>"` 造出的会话，web profile 能 `session/list` 到并打开。
- **会话选择没有 URL 路由**：它是客户端持久化状态 `localStorage['dsh.sessions.current'] = {"sessionId":"…"}`，开机时读取。因此必须在页面脚本之前写入——用 `Page.addScriptToEvaluateOnNewDocument` 预置再导航。
- **无会话首页只在没有工作区时出现**：有已持久化会话时 host 会按会话 header 的 `cwd` 自动 bootstrap 出工作区，之后开机自动导航进会话。所以 U01/U02 必须在造会话**之前**判定（本轮脚本分阶段 A/B，中间重启服务）。
- **非 loopback origin 下 `/api/*` 被 fence 拦**（Node 直连 403），必须走配对门控的 `/remote/api/*` 并带 `x-dsh-remote-device`；body 是 `{type:'client-request', rpcId, method, payload:{args:{…}}}`，且实参名按描述符（`session/list` 用 `_request`）。
- **配对限流**：`/pair-accept` 与 `/pair-app` 共用 page 桶（10 次 / 30 秒 / 源 IP），必须复用 `deviceId`。

**一条与预期相反、必须记录的实测契约**：宿主 intake 的原校验看的是**声明的 media type**，不做字节级校验。声明 `image/png` 而内容并非 PNG 的文件会被**正常加入草稿并拿到真实 ID**（U10 观测 `ok=true`）；`image/tiff` 这类不在支持列表里的类型也不被拒绝，而是按普通文件走 verbatim 上传路径（`isImageMediaType` 只把 png/jpeg/webp/gif 选进图片路径）。因此本轮**没有**把"非法图片必须被拒绝"写成判据——那会与实测契约相冲突；改判"每次导入只尝试一次 + 失败必带已知失败码 + 旧附件不丢"，这才是方案"校验拒绝或数量不符不自动重放"的实际可判定形式。可能的字节级校验发生在提交/上传阶段，不属 D08。
