# 让 V1 仅沿用 Harness 原生图片附件

V1 不建设通用 Windows 到 Linux 文件传输，只保留固定 Harness 已有的图片附件。图片由 Harness 页面提交、由 Harness 附件存储所有并与当前 Session 关联；它不是工作区中的原始文件。这样避免为 V1 引入新的 Linux 插件、上传路由、工作区写入契约和 Windows 原生桥接。

## Considered Options

- 建设通用文件传输：能力更完整，但需要新增跨端模块、认证数据通道、事务与清理策略，扩大 V1 的安全和分发范围。
- 只为图片建设自有模块：仍会复制 Harness 已有能力，并增加对页面扩展接缝和版本变化的耦合。
- 沿用 Harness 原生图片附件：不新增模块接口，由固定 Harness 继续负责图片格式、限额、归一化、持久化和错误呈现。

## Consequences

V1 只有 Harness 现有的图片拖放和剪贴板粘贴，不提供图片选择按钮、工作区图片落盘、共享草稿或自动重试。Windows 原生层不得读取或记录图片内容，目标窗口仍阻断全部下载。通用文件传输是未来独立升级目标，不得以隐藏开关、预留模块或 Linux 前置依赖进入 V1；Harness 或 WebView2 升级后必须重跑图片附件实机矩阵。
