# 使用能力契约与内置适配规则注册表承载第三方 WebUI

第三方 WebUI 的集合和依赖能力持续变化，静态 dsh-web 允许清单既不能覆盖未知同源 UI，也会把单一提供方的外部依赖变成所有页面的全局能力。启动器决定让不受信同源描述符只选择需求，由嵌入受 Authenticode 签名托管主程序集的只读注册表定义有限扩展能力；apphost、托管主程序集和安装器共同构成签名应用集。目标内容宿主与全局能力上限求交后固定唯一页面能力快照；这样纯同源 UI 无需登记，扩展依赖可审计，页面和用户都不能自行授权。

## Considered Options

- 持续扩充 dsh-web 专用常量：改动直接，但会形成封闭名单、全局 CSP 扩张和难以撤销的并行授权路径。
- 允许页面或用户提供规则：生态接入快，但把不受信输入变成安全策略来源，无法建立签名、版本、撤销和证据身份。
- 在线下载或独立规则包：可以更快更新，但引入第二套签名、更新、回退、离线和远程控制面，超出首版发布模型。
- 能力契约与内置注册表：更新必须发布完整签名启动器，但授权离线确定、可复现、可墓碑撤销，并复用现有正式安装身份。

## Consequences

新增技术无关的 `DshLauncher.Compatibility` 深模块；WebView 资源、方法、逐跳重定向、frame、条件 WebSocket/Worker 和 CSP 只消费同一不可变快照。描述符读取与本地兼容状态是生产/测试各有 adapter 的真实 seam；外部能力确认通过 host 表示层边界上的小型 port 完成，注册表本身不建立运行时可替换 port。Harness/LAN/route 基线只限定证据和支持范围，不作为不可可信取得的运行时匹配身份。临时配对和自动连接保持独立最小 CSP。任何规则变化都需要新的签名版本、注册表版本、影响清单、双 Runtime/Edge 证据和支持记录；运行时下载、手工导入、旧新规则并集与隐藏 fallback 不属于该架构。
