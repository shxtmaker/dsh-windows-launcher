# ADR 0007：管理改用独立客户端，远程界面内嵌显示（取代浏览器页面）

日期：2026-09-02

## 状态

已接受（取代 ADR 0006 中「独立 Web 管理页面」的部分）。

## 背景

0006 把 Windows 侧重构为配对集中端时，管理界面选择了「本机回环 Kestrel 托管的
独立 Web 页面 + 系统浏览器打开」，远程界面入口也在默认浏览器中打开
（`pair-app?device=<id>`）。实机使用反馈明确了两个不满：管理不应依赖浏览器；
远程界面作为核心使用面更不应跳出独立客户端。

## 决策

1. **管理回归原生客户端**：目标目录、配对、保活控制、诊断全部在 WPF 原生
   管理窗口完成；关闭窗口即最小化到托盘，保活继续；托盘菜单「退出」才是真退出。
2. **远程界面内嵌显示**：每个已配对目标可在客户端内打开一个 WebView2 窗口，
   直接显示 `pair-app?device=<id>`；按目标隔离的用户数据目录
   （`targets/<id>/udf`）承载浏览器状态；新窗口请求折叠回当前视图，
   DevTools 与默认右键菜单关闭。全程不调用外部浏览器。
3. **移除 Web 页面基础设施**：删除 `DshLauncher.WebUi`（Kestrel、JSON/SSE API、
   仪表盘页面）及对应测试；桌面不再引用 ASP.NET Core 共享框架，WebView2 SDK
   回归（1.0.4129.50，延续 V1 冻结基线）。
4. **核心枢纽不变**：`DshLauncher.Core` 的配对链接解析、配对传输、心跳保活
   调度与持久化契约原样保留；架构图收缩为 `Core ← Platform ← Desktop`。

## 后果

- `release-constants.limits` 移除 `webUiPort`；验证影响映射与固定依赖图同步更新。
- 集成测试改为直接引用 ASP.NET Core 框架（端到端模拟插件宿主仍在验收测试中）。
- 远程界面窗口依赖 WebView2 Evergreen Runtime（Windows 11 预装；缺失时客户端
  给出明确错误）；安装器自 V1 起已携带 Evergreen Bootstrapper。
- 管理能力不再暴露任何本地 HTTP 面：设备凭据只存在于枢纽内存与受保护的应用
  数据根中。
