# ADR 0009：应用图标采用原创 mascot 位图，不引用上游官方标志

日期：2026-09-04

## 状态

已接受。取代同日曾提出、随后作废的「上游官方标志几何 + Windows 11 容器」与「官方标志 + 网线
连接符号」两版方案；那两版的否决理由（不该把上游官方标志用作本产品的品牌标识）作为**长期约束
原样保留**在本 ADR 中。

## 背景

产品此前没有任何图标资产，`ApplicationIcon` 未设置，apphost 与托盘都用 .NET 默认图标。

曾实现过两版自绘图标，主体几何都逐点取自上游 DeepSeek Harness 官方 `favicon.svg`。两版都可
复现生成并通过验收测试，但均被判作废，否决理由是**不该把上游官方标志用作本产品的品牌标识**：
本仓库与上游是独立项目，产品只是上游服务的一个配对客户端；把上游标志放进自己的应用图标，会让
任务栏、开始菜单、资源管理器和「应用和功能」列表里出现的图标声称自己就是上游官方产品，属于
归属误导。上游素材以 MIT 发布（见 `eng/fixtures/linux/LICENSE.deepseek-harness`），但 MIT
不授予商标权。

第三版尝试用细节插画直接作图标，实测否决：人脸缩到 16/24px 就是一团蓝色噪点，这是像素数量
决定的，不是审美问题。最终采用产品方提供的 mascot 位图（蓝发、眨眼、女仆头饰、深蓝服饰与
宝石领结），并按尺寸分档处理。

## 决策

1. **长期约束：不以上游官方标志（或其任何可识别几何变体）作为本产品的图标、徽标或品牌元素**。
   包括直接收录官方 `favicon.svg`、描点重绘、在其轮廓上叠加装饰（如连接符号），以及把它当作
   「主体」再套自己的容器与配色。同时不使用任何微软徽标图形（四格旗帜等）。
2. **图标源是位图，不是矢量**：`assets/brand/mascot-source.png`（1254×1254，满幅方形构图，
   自带圆角容器与白色四角）。它由产品方提供，是本仓库唯一的设计输入。
3. **按尺寸分两档，小尺寸档改用脸部放大裁切**：
   - ≥40px：整幅构图直接适配；
   - ≤32px：以 `(0.55, 0.56)` 为锚点放大 `1.85×` 裁切，让脸填满画面。不这么做的话 16px 上
     只剩头发，认不出是人脸。
4. **白色四角换成真透明**：`eng/make-app-icon.ps1` 用自己的圆角矩形遮罩（半径 0.23×边长）
   裁掉源图的白色圆角外区。半径必须 ≥ 源图自带圆角，否则任务栏上会拖出白边；这一条由验收测试
   断言 PNG 的 `color type == 6`（RGBA）来兜底。
5. **不做图块检测**：源图角色头发溢到画布边缘，投影法拿不到干净的图块边界（实测失败），
   因此固定「整幅方形 + 自有遮罩」，参数以显式令牌写在脚本顶部。
6. **渲染与打包**：WPF（`DrawingVisual` + `RenderTargetBitmap`）4 倍超采样后 HighQuality
   降采样；`.ico` 中 ≤64px 帧写成 32bpp DIB（含 AND 掩码），≥128px 帧写成 PNG。裁切靠变换
   实现——`DrawingContext.DrawImage` 只有 `(image, rect)` 两参重载，没有源矩形版本。
7. **产物提交 + 复现门禁**：`assets/brand/app/DshWindowsLauncher.ico` 与逐尺寸 PNG 预览入库，
   构建与打包不重新生成；`-Verify` 重画到临时目录逐字节比对，由 Acceptance 测试
   `ApplicationIconIsReproducibleAndWiredIntoEverySurface` 调用。
8. **接入面**：csproj `<ApplicationIcon>`（apphost → 资源管理器、任务栏、Alt+Tab、快捷方式、
   卸载显示图标、WPF 窗口默认图标）+ 三个 `.iss` 的 `SetupIconFile`（缺文件时 ISPP `#error`
   拒绝编译）。不做 `Window.Icon` 的 HICON 桥接：WPF 在 `Icon` 未设置时回落到 exe 内嵌图标。

## 后果

- 图标是 AI 生成的位图素材，其可版权性与来源链条在多数法域仍不确定；仓库只记录「由产品方提供」，
  不声称原创著作权。对外发布前需要重新评估这一点。
- 源图 2.3 MB 入库，是仓库最大的单个资产；换图会带来同量级体积变化。
- 小尺寸档与大尺寸档是**两套构图**（整幅 vs 脸部特写），视觉上不再完全一致——这是为了
  16px 可读性刻意做的取舍，与 Fluent / iOS 图标集提供多套缩放变体是同一类做法。
- 更换 mascot 需要替换 `mascot-source.png`、重新生成、并按新图重测脸部锚点与放大倍数；
  不存在手工修图路径。
- 这条约束是设计层面的，代码门禁无法强制：没有任何检查能阻止某人把上游标志塞进
  `ApplicationIcon`，评审时需人工把关。
