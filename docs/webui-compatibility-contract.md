状态：实施基线<br>
更新日期：2026-08-31<br>
关联文档：`v1-implementation-plan.md`、`v1-release-checklist.md`、`webui-provider-onboarding.md`、`reference-adapters/dsh-web.md`

## 1. 目的、范围与术语

本契约定义 DSH Windows Launcher 如何承载由同一 Harness 目标端点提供的第三方 WebUI。目标是让 Windows 显示 Linux 侧服务端当前选择的同一界面，同时保持逐目标会话、单目标内容宿主和浏览器安全边界。

契约兼容 WebUI 必须由已配对 Harness 目标的根页面呈现，沿用该目标的 Cookie 会话和业务 route。独立业务 URL、第二个 Harness 目标端口、第二套认证入口、反向代理页面或普通网站不属于本契约。适配规则审核过的外部 HTTPS origin 可以带显式端口；它仍只是受限依赖，不成为新的 Harness 目标。

“服务端界面一致性”表示 Windows 与 Linux 客户端呈现同一目标端点基于相同服务端状态选择的界面和功能。它不复制 Cookie、Web Storage、窗口布局、主题或其他浏览器本地状态，也不承诺逐像素相同。

“页面能力周期”从内容宿主为一次可见根导航创建受限浏览器上下文开始，到该 Document 被替换、关闭或因 renderer/browser/environment 恢复而废弃时结束。描述符读取、规则匹配、确认、快照和强制属于同一周期；该周期创建的 `blob:` 所有权随周期结束而失效。

## 2. 兼容层级与全局能力上限

### 2.1 基础兼容

未登记的契约兼容 WebUI 只要完全依赖以下能力，即可获得基础兼容：

- 当前精确目标 origin 的顶层文档、脚本、样式、字体、图片、媒体、API、SSE 和其他普通 HTTP 资源；
- 父 Document 属于当前精确目标 origin、目标仍是该精确 origin 的任意同源 frame，以及由该父 Document 创建且不含 `srcdoc` 的 `about:blank` 派生文档；
- `data:` 图片和 WebGL；
- 由当前目标 Document 创建、可追溯且归属当前页面能力周期的受限 `blob:` 图片、媒体和下载以外的数据读取；
- 页面编辑、页内查找、缩放、用户触发的图片拖放和粘贴。

基础兼容不要求提供方登记、Windows 规则或用户确认。描述符缺失、无效、未知或规则未命中时，页面最多获得基础兼容。

精确目标 WebSocket 是条件能力，不由 `1.0.0` 基础兼容授权。它只有按 2.3 完成门禁并由更高契约版本显式纳入后，才可成为该版本的基础能力。

### 2.2 扩展兼容

WebUI 需要受限外部依赖时，必须同时满足：

1. 当前目标通过同一浏览器会话提供有效兼容描述符；
2. 描述符中的精确身份、版本和 adapter key 命中只读内置适配规则；
3. 规则只允许精确 HTTPS origin、显式端口、窄路径和有限资源类型；
4. 被动资源只允许 `GET`/`HEAD`，经审核 API 只允许 `GET`/`POST`/`OPTIONS`；
5. 规则内容位于全局能力上限内；
6. 目标内容宿主形成确定且不可变的页面能力快照；
7. 首次出现或变化的外部影响已经由用户按目标接受；
8. 该精确身份完成适用一致性和发布门禁。

Harness 主页面不得直接加载外部脚本。只有被精确审核的跨 origin frame 可以在自身 origin 内加载完成该窄用途所必需的脚本；脚本 origin、路径、方法、资源类型和 frame 父子关系都必须进入同一规则与快照。

描述符、页面脚本、用户输入和用户确认均不能创建规则或直接产生能力。审核外站可以依浏览器原生 Cookie、SameSite、CORS 和 CSP 保存自身状态；启动器不得读取、注入、导出这些状态，也不得用它们替代 Harness 配对。

### 2.3 条件能力门禁

精确目标或外部 WebSocket、Dedicated Worker、Shared Worker、AudioWorklet、OOPIF、逐跳重定向和 CDP Fetch 都是条件能力。每项能力只有同时满足以下条件，才可进入某个后续契约版本：

1. 在固定最低 WebView2 Runtime 与验证时当前 Evergreen 上完成正向、负向、恢复和拒绝请求未到站证据；
2. 同 endpoint Edge 对照完成故障归因；
3. 新的契约版本和规范化能力清单显式加入该能力及精确强制边界；
4. 签名候选、内置规则、fixture、影响清单和支持记录绑定同一证据身份。

门禁完成前，该能力为“不受支持”，不能由基础兼容、规则、用户确认或实现存在推定为允许。`1.0.0` 不授权上述条件能力。

### 2.4 永久禁止项

任何 WebUI、描述符、适配规则和条件能力版本都不能开放：

- `about:srcdoc`、Service Worker、持久离线响应和后台页面执行；
- `unsafe-eval`、`wasm-unsafe-eval`、Document 自声明执行开关，以及由规则扩大的 `blob:` script；
- 下载、保存网页、打印到文件和 Linux 到 Windows 文件传递；
- 通知、摄像头、麦克风、位置、后台剪贴板读取和其他页面权限；
- 证书错误绕过、把 RFC1918 HTTP 伪装成安全上下文、Basic Auth 和客户端证书；
- DevTools、默认浏览器菜单、HostObject、WebMessage、共享缓冲区、文件系统对象或其他原生桥接；
- `file:`、`javascript:`、未知 scheme、任意外部协议或非用户触发的系统浏览器跳转；
- 任意主机通配、裸 `https:`/`ws:`、任意 CDN、主页面外部脚本、未审核外部脚本或任意外站 iframe；
- 页面或用户在运行时添加域名、路径、方法、CSP source 或例外。

`'unsafe-inline'` 和 `blob:` script 只能作为版本化全局 CSP 债务经 A/B、双 Runtime 和签名候选证据冻结，不能由任何适配规则扩大。不同 `blob:` 资源类型分别判定，不能用图片或媒体许可推导 script、Worker 或下载许可。

规则包含任何超出上限的能力时，整条规则无效。不得静默裁剪后继续使用。

## 3. 信任责任

| 主体 | 责任 | 不拥有的权力 |
|---|---|---|
| WebUI 兼容描述符 | 声明组件稳定身份、精确版本、契约版本和预定义 adapter key | 不认证页面，不声明原始授权规则，不直接授权 |
| 内置适配规则注册表 | 保存经过 Windows 审核、在被同源页面冒用时仍安全的正向规则 | 不接受页面、本地散落 JSON、命令行、环境变量或用户添加规则 |
| 目标内容宿主 | 读取和验证描述符，匹配注册表，与全局上限求交，生成并强制页面能力快照 | 不猜测 UI，不补第三方认证，不动态扩大当前 Document 能力 |
| route owner | 保证 Host/Origin、会话、CSRF、数据权限和错误语义符合已提交 route 契约 | 不把业务失败转化为宿主权限例外 |
| 用户 | 接受、拒绝或撤销已审核外部影响 | 不编辑规则，不添加域名，不突破全局上限 |
| 页面脚本 | 使用当前快照已经允许的 Web 能力 | 不提供描述符响应，不修改注册表，不触发即时授权 |

`uiId`、包名、仓库、adapter key 和用户确认都不是密码学身份。每条规则必须在任意同源代码冒用其声明时仍保持安全。最终授权主体是整个同源页面，不存在逐插件浏览器沙箱。

## 4. 描述符协议

描述符固定地址为：

```text
/.well-known/dsh-webui-compatibility.json
```

目标内容宿主使用当前目标同一个 WebView2、UDF 和 Cookie 会话，在可见根导航前读取。只接受：

- 当前精确目标 origin；
- 无重定向；
- HTTP `200`；
- `Content-Type: application/json; charset=utf-8`；
- 响应不超过 64 KiB；
- 组件不超过 64 个；
- 有限 JSON 嵌套深度。

V1 顶层授权字段只允许：

```json
{
  "schemaVersion": 1,
  "contractVersion": "1.0.0",
  "components": [
    {
      "uiId": "<stable-namespaced-id>",
      "uiVersion": "<exact-semver>",
      "sourceRev": "<optional-immutable-revision>",
      "adapterKeys": ["<predefined-key>"]
    }
  ]
}
```

`contractVersion` 和 `uiVersion` 都是精确规范化 SemVer。当前只接受 `contractVersion=1.0.0`；更高版本必须由对应启动器显式支持，未知版本整体降级为基础兼容。prerelease 只允许精确匹配。Git 或本地构建使用不可变 `sourceRev`。禁止范围、`latest`、邻近版本、运行时最高版本选择和从 HTML、脚本、包名或资源路径猜测版本。

解析器拒绝重复 JSON 键、尾随内容、重复组件、同一身份冲突版本、非法 adapter key、未知主版本和任何试图声明 origin、路径、方法、CSP、权限或原生能力的字段。非授权扩展元数据只能位于独立命名空间，解析器可以忽略且不得改变能力结果。

结构正确的描述符允许部分匹配：已知组件参与规则计算，未知组件没有扩展能力并进入部分兼容诊断。结构错误、冲突身份或非法授权字段使整个描述符无效。

描述符每个页面能力周期重新读取。缓存只用于脱敏诊断，不能参与授权。

## 5. 内置适配规则注册表

每条活动规则至少包含：

- `ruleId`、不可变 SemVer `ruleVersion`；
- 支持的 `contractVersion`，以及只用于证据和支持范围的 Harness/LAN/route 基线；
- `uiId`、闭合版本范围、可选 `sourceRev`；
- 可响应的 adapter key；
- 精确 HTTPS origin、显式端口、路径、资源类型、HTTP 方法、重定向和 frame/WebSocket/条件 Worker 范围；
- 用户可见用途和脱敏诊断名称。

规则只表达正向允许项，不建立规则级 deny 覆盖。所有 URI 使用规范化 scheme、IDNA host 和显式有效端口；禁止 userinfo、通配主机、裸 scheme 和 fragment。路径只接受精确匹配或具有路径段边界的窄前缀；拒绝编码分隔符、点段、重复解码和双重解释。query 可以限制键名，但敏感值不得进入快照摘要、UI、日志或证据。

注册表构建必须证明一个完整匹配元组最多对应一条活动规则。版本范围不得重叠，不在运行时选择“最高”或“最接近”规则。完全相同的能力去重，不同安全允许项在全局上限内取并集。rule ID/version、adapter key、用途或能力出现冲突时，页面扩展能力整体失效。

Harness/LAN/route 基线不是运行时授权匹配维度。现有客户端没有可独立信任的精确基线信号；把同源描述符或探测分类当成认证只会制造伪安全。基线只限定规则审核、fixture、支持记录和影响清单；每条规则仍必须在同源页面冒用身份且底层基线不同的情况下保持安全。

### 5.1 字节级规范化与摘要

描述符、契约能力清单、注册表、墓碑、快照、接入包、审核决定、支持记录和结构化证据共用以下规范化规则：

1. 先按各自 Schema 拒绝重复键、浮点数、超出 IEEE-754 安全整数的数值、未知授权字段和非法 Unicode；所有文本先规范化为 Unicode NFC。
2. SemVer 解析后输出其唯一规范文本；URI 输出小写 scheme、IDNA ASCII 小写 host、显式有效端口、移除点段后的路径和规范百分号编码，禁止 userinfo、fragment、默认端口省略和二次解码。
3. 语义无序数组在 Schema 指定的身份键上排序：组件按 `uiId/uiVersion/sourceRev`，adapter key 按字节序，规则按 `ruleId/ruleVersion`，墓碑按 `ruleId/revokedFromRegistryVersion`，能力按完整规范能力对象。Schema 明确标为有序的逐跳条件保持原顺序。
4. 规范模型使用 RFC 8785 JSON Canonicalization Scheme 输出。对象键按 JCS 排序，不写无意义空白；字节编码固定为 UTF-8、无 BOM、无尾随换行。
5. `SHA-256` 对上述精确字节计算并以小写十六进制表示。构建器、运行时、包清单和证据生成器必须对同一 fixture 产生相同字节和摘要。

非规范输入可以被解析器拒绝；不得在不同模块各自实现“近似规范化”。规范化器是 Compatibility 模块的单一实现，Schema fixture 锁定跨模块结果。

### 5.2 版本与墓碑

- `registryVersion` 是规范化注册表内容的单调递增整数；任何规则、范围或撤销变化都增加版本。
- `ruleVersion` 是单条规则的不可变 SemVer；相同 `ruleId + ruleVersion` 永远对应相同规范内容。
- 新增支持身份或能力提升启动器 minor；规则修正、收窄和撤销提升 patch；破坏性 Schema、契约或全局能力模型变化必须提升 launcher major。
- 安全撤销用永久墓碑保存原 `ruleId`、撤销起始版本、严重级别和脱敏原因码，不包含允许能力，优先于活动规则，rule ID 永不复用。

注册表只作为规范化只读资源嵌入受 Authenticode 签名的托管主程序集。apphost EXE、托管主程序集和安装器共同构成签名应用集；打包与启动前校验托管程序集签名、规范注册表摘要及其与发布常量的一致性。禁止运行时下载、后台更新、独立规则包、手工导入、散落文件或远程 kill switch。

## 6. 页面能力快照与确认

目标内容宿主完成描述符和注册表计算后，生成不可变页面能力快照。摘要至少绑定：

- `targetId`；
- 全部组件的 `uiId`、精确 `uiVersion` 和 `sourceRev`；
- 实际命中的 `ruleId`、`ruleVersion`；
- 最终规范化页面能力集合。

首次出现外部能力或摘要发生任何变化时，原生 UI 显示精确站点、能力类型和用途，由用户按目标接受或拒绝。身份、版本、revision、规则、能力扩大、缩小和降级都形成新摘要并重新确认。只有摘要完全一致才可复用既有确认。

用户拒绝或撤销、规则被墓碑撤销、描述符缺失/失败/降级、注册表损坏或水位异常时，只保留基础兼容。不得复用旧描述符、旧快照或旧确认维持表面可用。

单个 Document 生命周期内快照不可扩大。未包含的请求直接阻止，不弹出即时授权。打开、刷新、重开、renderer/browser/environment 恢复和重新配对后的首次可见导航都重新执行完整页面能力周期。

## 7. 统一强制与 CSP

资源、HTTP 方法、每个重定向跳、frame、条件 WebSocket、条件 Worker 和追加的 Document CSP 必须消费同一快照。前一跳允许不继承到后一跳。WebSocket 精确比较 scheme、host 和 port。

服务端返回的全部 CSP 头原样保留；宿主只对当前目标的 Document 响应追加独立且不更宽松的策略，不改写跨 origin 或静态资源响应。策略禁止 `*`、裸 `https:` 和裸 `ws:`。目标 WebSocket source 只有在当前契约版本授权该条件能力时才由绑定 authority 精确生成。

单个可选资源或 WebUI 声明的必需外部 frame 失败时，安全根页面保持可用，兼容状态标记为功能受限或该支持身份不符合，并显示窄提示。只有 Harness 根导航不可用、证书/协议失败或检测到全局安全边界违反时，才进入完整阻断/恢复页。

临时配对和自动连接 WebView 是独立安全流：关闭页面脚本，只允许绑定目标 origin 的最小请求和 CSP，不读取描述符、注册表、适配规则、外部能力确认或可见页面快照。

## 8. 兼容状态与诊断

兼容状态不与目标连接状态混用。安全根页面可用但扩展能力缺失时，页面保持可操作，原生窄提示显示“部分功能受限”，按需侧板提供：

- 兼容层级；
- 契约、Schema、注册表和命中规则版本；
- 脱敏外部站点与用途；
- 稳定原因码；
- 重新打开、刷新、撤销确认或查看提供方说明等安全恢复动作。

UI 不提供临时放行、添加域名、编辑规则或忽略证书入口。诊断只允许版本、阶段、规范化摘要和脱敏原因；禁止描述符原文、query 值、Cookie、请求/响应体、页面内容、图片、业务数据和未脱敏绝对路径。

## 9. 本地状态与回退

应用数据根分别保存：

- 全局注册表回退水位；
- 逐目标外部能力确认；
- 逐目标脱敏兼容诊断缓存。

三类记录使用独立 Schema、原子替换、上一版有效备份和所有权检查，不写入 `targets.json`。只有当前内置注册表完整校验成功后才能提高水位。当前版本低于水位、记录属于未知新 Schema、注册表摘要/唯一性/匹配确定性失败时，全部目标只保留基础兼容；不使用备份注册表、缓存规则或可解析子集。

忘记目标删除该目标确认和诊断缓存，不降低全局水位。数据清除卸载可以明确删除水位；删除后再安装旧版本属于无法从本地历史识别的不受支持边界。

## 10. 证据与支持声明

证据状态严格区分：

- **基础契约符合**：提供方套件证明精确版本只依赖基础能力；不表示 Windows 已逐项验收。
- **内部扩展规则候选**：规则与自动测试可评审；尚未形成支持。
- **扩展兼容受支持**：规则进入正式签名安装包并通过适用 Windows 门禁。
- **参考适配器已验证**：精确参考版本通过正负回归、双 Runtime、Edge、签名候选和支持记录绑定。
- **不符合契约**：依赖全局上限外能力、身份不可确定或门禁失败。

提供方一致性结果、接入包、审核决定、内置注册表、支持记录和发布证据必须绑定同一兼容证据身份。`FAIL`、`SKIP`、`MISSING` 或身份不一致阻止对应正式声明。基础兼容 WebUI 不进入枚举白名单；支持记录只列经过正式审核的精确扩展身份和参考适配器，且不参与运行时授权。

提供方角色、状态机、接入字段、原因码、复核、弃用和开放门槛见[提供方接入与维护规范](webui-provider-onboarding.md)。具体 VFY、RS、双 Runtime、Edge、性能和发布退出见[V1 发布检查表](v1-release-checklist.md)。

## 11. 版本变化和维护

WebUI、组件、`uiVersion`、`sourceRev`、route、外部依赖、Harness/LAN、WebView2 Runtime、契约、Schema、注册表或 CSP 债务变化时，必须按版本控制的影响清单计算重验并集。身份未变但行为变化属于身份违规，暂停对应支持声明。

规则安全问题通过新的完整签名 patch 和永久墓碑处理。未安装补丁的旧客户端仍执行旧内置注册表；项目不声称远程停用。非安全退出先在至少一个签名版本中计划弃用，再用墓碑结束扩展能力。离线规则不按系统时间过期；治理复核逾期只暂停新承诺。

本契约实现完成不等于正式提供方流程已经开放。负责人、公开接入入口、私密安全入口、签名发布身份、支持记录和完整参考流程存在占位值时，只能发布基础兼容自助材料。
